# 0.3.0 · 日志与 SnapRAID 只读监控

## 已实现

- 上传与 SnapRAID 日志保存在 data/photosync.sqlite3 的 audit_logs 表，重启保留。
- 上传记录包含时间、请求方法、HTTP 结果、文件名、会话 ID、偏移、请求字节数及完成后的 SHA256 / 去重结果。记录创建、分片、进度查询、完成、取消和请求失败；不保存文件内容、认证头或密钥。
- 0.2 及更早版本的 events 在首次升级时导入日志中心一次，不丢弃历史上传事件。
- 日志中心按来源、级别筛选，ID 游标分页，每页 100 条；可展开详情与导出当前已加载记录的 JSON。
- SnapRAID 页面查看最近 100 条检查日志；完整历史可在日志中心查询。
- 后台启动检查及定期检查、手动异步检查、超时、挂载/身份检查、状态命令结果记录；告警状态和已知晓标记持久化。
- 全局告警横幅每 15 秒更新。状态请求超过 10 秒或断连显示未知。确认告警不解除故障。

接口：GET /api/v1/logs?category=upload|snapraid&level=info|warning|error&before=ID；GET /api/v1/snapraid；POST /api/v1/snapraid/check；POST /api/v1/snapraid/acknowledge。

## 启用 SnapRAID 监控

默认未配置，显示未知；不会假装磁盘已受保护。应用仍可正常上传。

```bash
python3 -m server.app --snapraid-monitor-config /path/to/monitor.json
```

配置示例见 config/snapraid-monitor.example.json。只从服务器本地配置文件读取命令与路径，网页不能提交任意 shell 命令。运行的是固定参数列表 `snapraid -c CONFIG status`，不执行 shell。

- interval_seconds 默认 3600，最小 30；timeout_seconds 默认 30，范围 1–120。
- mounts 必须列出所有需要检查的数据盘和校验盘。每个路径必须实际为挂载点，并预先包含 `.photosync-volume-id` 文件，其文本须与 identity 一致。应用不创建这些标记或格式化磁盘。
- 容器绑定挂载能否被正确识别、标记与实际物理盘的关联仍需目标 PVE 环境验证；不能将路径存在等同于盘身份正确。
- 建议为此服务仅提供执行 status 和读取必要文件的权限，不要配置 sudo 任意命令。

检查失败显示严重异常；未配置、依赖不可用、超时、超过两次检查周期未更新显示未知。即便 status 退出码为 0，仍显示“需要关注”：本版尚未解析不同 SnapRAID 版本的完整状态、最后成功 sync 时间和 scrub 历史，不能确认无错误或校验新鲜度。原始命令输出保存在日志详情中（最多 64 KiB）。

检查之间由进程内锁防止重叠，单实例使用。跨进程/与外部 daemon 的共享锁尚未实现。snapraid sync / scrub / fix 调用尚未开放；已有外部磁盘维护任务时应先协调调度，不能视为生产环境自动运维方案。

## 范围与限制

- 当前记录服务器实际观察到的请求。尚未发出请求的客户端错误、不再发请求的断网/关闭浏览器，不能立即形成服务端失败事件；部分会话可保持未完成并续传。
- 日志默认保留全部，无自动清理；大量分片会产生大量日志，须预留数据库空间。保留期限、归档、磁盘空间预警仍待完善。
- 本地服务无登录，日志中可能含照片文件名和磁盘路径，只适用于受信任的本机评审环境。
- 告警首次发生/恢复时间的独立事件模型、站外通知、sync/scrub 调度、空间阈值、跨进程锁和真实磁盘恢复仍是后续工作。
- 数据库 schema 3：添加日志、迁移标记与监控状态表，保留原片、上传会话和 Live 配对。升级前备份 data/。
- 测试使用隔离的模拟命令结果验证失败分支，没有操作真实 SnapRAID 阵列；MS-R1 / PVE 实机验收尚未完成。
