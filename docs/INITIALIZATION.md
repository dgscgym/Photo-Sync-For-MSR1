# 现有媒体目录索引

首次引导和登录已在 0.5.0 调整为独立页面，参见 [SETUP.md](SETUP.md)。下文描述目录索引行为。

## 原则

媒体原片与应用版本、数据库、缩略图分离。现有目录只读索引，不要求复制到 PhotoSync 专用目录，不改文件名或目录结构，不删除磁盘文件。SHA256 是内容身份，目录路径是可重新绑定的位置；已有相同文件可以登记多个位置，相册只显示一项。

“任意结构”指支持递归读取不同层级、文件命名及无扩展名的受支持原始媒体，不代表能解密其他软件的专有加密仓库、解析任意数据库或支持全部媒体编码。旧相册的 thumbnails / previews 也可能是合法媒体，扫描前应选中真正原片范围，当前没有自动识别第三方相册目录语义的能力。

## 初始化流程

1. 在容器中映射原有照片盘，建议外部媒体根目录只读挂载；应用 data/ 单独持久化并可写。无需移动照片。
2. 启动时通过可重复的 `--library-base` 参数授权媒体范围。默认不允许网页登记任意系统目录。
3. 首次打开进入“目录管理”，显示授权目录；输入服务端目录、可读名称，登记并扫描。
4. 完成初始化进入照片库；也可以跳过目录登记，先使用上传。后续可随时返回该页增加目录、重绑路径或重扫。

```bash
python3 -m server.app \
  --data /var/lib/photosync \
  --library-base /media/photos \
  --library-base /media/old-library \
  --scan-interval 300
```

输入容器里的路径而不是宿主路径。不要把系统根目录、密钥目录或整个项目目录授权给扫描器。只有所需媒体范围应被映射。

## 导入与日常使用

- 注册后立即后台扫描，启动时及之后默认每 300 秒自动扫描（最小 30 秒），可手动触发。当前采用轮询，不是实时文件监听。
- 递归按内容签名识别 JPEG、PNG、GIF、WebP、HEIC/HEIF、MP4/MOV 与 EBML 视频；编码能否预览取决于浏览器和 FFmpeg。RAW 与嵌入式 Motion Photo 等不在本版支持范围。
- 扫描全文件计算 SHA256，内存不随视频体积增长；大量原片会产生较多磁盘读取，初次及周期扫描耗时需 MS-R1 实测，暂未做元数据缓存优化。
- 不跟随符号链接。已知临时后缀 .part / .partial / .tmp / .crdownload 跳过；正在变动或两秒内修改的文件暂缓，下次再尝试。
- 手动复制文件建议先写临时后缀，完成后原子改名。两秒稳定检测无法判断暂停写入很久的文件是否已经完整；当前只检查签名，不做完整解码校验。
- 改名、目录内移动或换目录层级：重扫后按 SHA256 识别同一内容，不生成新原片副本。
- 挂载路径改变：在来源卡片选择“重新绑定”，修改为新的授权目录路径，保留来源 ID 后重新扫描。需要先更新容器挂载 / library-base 授权。
- 介质离线或扫描中断：保留已有照片索引，来源显示离线；不会根据失败扫描清除位置，也不会删除原片。
- 成功完整扫描后发现文件不在原位置：位置标为不可用，照片历史仍保留。改变内容则产生新的 SHA256，旧内容仅在仍有可用位置时可读取。
- 原片读取与 FFmpeg 转码使用统一位置解析器，支持直接读取外部媒体，无需额外原片复制。

## 升级与重建

- 当前新增 schema 4：来源、相对路径位置及初始化设置。升级旧 schema 前自动用 SQLite backup 保存元数据副本到 data/metadata-backups/，保留照片、日志和 Live 配对。
- 发现比程序支持版本更高的 schema 时拒绝启动，不自动降级或清空数据库。未来版本仍须遵循迁移规则；不能保证未知版本能直接打开数据库。
- 日常升级复用原来的 data/ 和媒体挂载，不要求换目录。目录结构变化通过重扫或重绑处理。
- 数据库丢失时可将现有原片目录重新登记并扫描，重建文件级索引；包括明确授权的旧 data/originals 目录，其文件无扩展名也可识别。不会恢复已经丢失的人工人物命名或其他数据库专有信息。
- “导出索引清单”提供版本化 JSON（format_version=1）：照片元数据、来源、相对路径、SHA256 与 Live 配对。它不包含原片，不是数据库备份；本版尚未提供清单导入 / 一键恢复，需继续备份完整数据库。

## API

- GET `/api/v1/library`：初始化、授权范围、来源、扫描状态。
- POST `/api/v1/library/sources`：JSON `{path,name,source_id?}`；新来源或重绑。
- POST `/api/v1/library/scan`：异步扫描请求。
- POST `/api/v1/setup/finish`：完成引导并撤销会话，需先接入或明确跳过 SnapRAID。
- GET `/api/v1/library/manifest`：导出版本化清单。
- 目录登记及扫描日志进入日志中心的“目录导入记录”。

## 验证与后续

已在隔离临时目录测试：嵌套结构、无扩展名、多个位置去重、改名、挂载目录迁移重绑、手工添加、离线保留、写入中跳过、符号链接越界、旧 schema 备份和拒绝新 schema。未修改真实照片盘。

尚未完成：大规模 MS-R1 性能、文件监听、目录浏览选择器、单文件变化历史 UI、清单恢复、第三方人物/相册元数据迁移、真实 PVE 绑定挂载验收和初始化页面视觉验收。SnapRAID 对新增来源的保护范围不会自动改变，必须另行配置并验证。
