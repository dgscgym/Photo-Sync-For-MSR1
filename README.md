# Photo-Sync-For-MSR1

面向铭凡 MINISFORUM MS-R1（此芯 P1 / ARM64）的私人照片管理与加密云备份项目。

> 当前版本：**0.2.0 媒体上传原型**。已实现最大 10 GiB 分片续传、精确去重、照片/视频预览、显式 Live Photo 配对和活动记录；人脸识别、NPU、加密归档和 115 同步尚未实现。下方需求描述是完整目标，不代表所有功能已完成。

详见 [大视频、Live Photo 与 MS-R1 验证说明](docs/MEDIA.md)。FFmpeg 为可选依赖，软件转码尚未在 MS-R1 实机验证。

## 快速启动原型

需要 Python 3.9+，无第三方依赖：

```bash
python3 -m server.app
```

浏览器打开 http://127.0.0.1:8080。使用 Ctrl+C 停止。原片与 SQLite 数据默认保存在 `data/`，重启后保留。

```bash
# 自定义端口与持久化目录
python3 -m server.app --port 8081 --data /path/to/photosync-data
# 运行集成测试
python3 -m unittest discover -s tests -v
```

原型仅用于受信任的本机环境，无登录和 TLS；默认只监听回环地址。尚未在 MS-R1 上验证。不应直接向公网开放。文件签名检查不是完整图片解码验证。

- `client/`：响应式浏览器客户端，照片库、上传、预览、活动以及功能占位页面。
- `server/`：HTTP API、SQLite 元数据、内容寻址原片存储。
- `tests/`：并发去重、重启持久性、原片读取及请求边界测试。
- [API 说明](docs/API.md) · [版本管理规则](docs/VERSIONING.md) · [变更记录](CHANGELOG.md)

当前先制作独立客户端 / 服务端原型用于交互和接口验证，最终是否复用现有相册仍可在后续评估。

## 1. 项目目标

对标 Immich / PhotoPrism 的照片上传、浏览及人物相册体验，重点实现：

1. 上传照片并按人物自动归类，不做视觉问答。
2. 基于原始文件 SHA256 去重，重复上传不产生多余的原片副本。
3. 自动将新增照片分批打包、加密，并同步到 115 网盘。
4. 评估此芯 P1 内置 NPU 对人脸检测与特征提取的加速能力。
5. 面向 MS-R1 的 Debian / ARM64 环境部署，并评估 PVE 下的可维护部署方式。

## 2. 已确认的需求方向

### 2.1 照片管理与人物相册

- 提供照片上传工具，以 Immich / PhotoPrism 为产品参考。
- 检测照片中的人脸，提取人脸特征，对同一人物的照片进行归类。
- 人像识别用于照片整理，不需要聊天、图片问答或生成式视觉语言模型。
- 产品基线拟包含：照片列表、时间线、原图查看、处理状态和人物相册；具体首版范围待确认。
- 拟提供人物命名、合并、拆分和误识别纠正，避免自动分类错误无法修复。

### 2.2 SHA256 精确去重

- 服务端根据上传的原始文件内容计算 SHA256，不信任客户端提供的哈希作为最终依据。
- 同一存储范围内，相同 SHA256 的文件只保存一份原片；再次上传返回已有资源或关联到已有文件。
- 同时上传相同文件也不能产生重复原片；需要数据库唯一约束及文件落盘的幂等处理。
- 重复上传不重复生成缩略图、执行人脸分析或进入新的云端归档包。
- 哈希针对完整原始文件；修改 EXIF、重新压缩或转格式后的文件可能有不同哈希，按不同文件处理。
- 画面相似但字节不同的照片，暂不自动合并或删除。
- 缩略图、人脸裁剪等衍生文件与原片分别管理，不计作重复原片。
- 若支持多用户，文件去重不能绕过各用户的资源权限；具体去重范围待确认。

### 2.3 自动加密归档与 115 同步

- 后台自动将新增照片组成增量归档包，分批上传到 115 网盘。
- 采用可配置的时间或容量阈值触发打包；具体阈值待实测确定。
- 使用成熟的加密方案，不自行设计密码算法；最终格式和密钥管理方式待验证确定。
- 云端不应暴露原始文件名、照片元数据或明文归档清单。
- 维护照片 SHA256、归档包、包内路径及远端标识之间的索引；可恢复清单随包加密保存。
- 打包和上传需幂等；任务重试不得将同一照片反复归档。
- 中断后可恢复任务，保留失败原因，支持重试；断点续传取决于所选 115 接口能力。
- 记录打包、加密、上传、校验等阶段的状态，不能仅因请求发出就标记备份成功。
- 支持下载、解密和恢复，恢复后以原片 SHA256 校验内容一致。
- 首版建议保留本地原片；自动清理本地原片需另行确认。
- 115 是加密备份目的地；加密包内的照片不能依赖 115 直接在线浏览。
- 加密密钥需要独立备份，恢复流程不能只依赖原 MS-R1 上的数据库和配置。

## 3. 部署与 NPU：待验证的技术方向

### 3.1 目标环境

- 硬件：铭凡 MS-R1，此芯 P1，ARM64。
- 系统：Debian；如使用 NPU，需要兼容的此芯内核、驱动和用户态运行时。
- 虚拟化：用户希望使用 PVE；具体版本、软件源和宿主机内核待验证。
- 容器与依赖必须具备 ARM64 支持。

### 3.2 人脸处理流水线

```text
照片上传 → SHA256 去重 → 保存原片 → 后台照片处理
                                      ├─ 缩略图 / 元数据
                                      ├─ 人脸检测 → 对齐 → 特征提取 → 人物聚类
                                      └─ 增量打包 → 加密 → 115 同步 → 恢复校验
```

拟由 NPU 承担人脸检测和特征提取；解码、对齐、聚类、SHA256、加密和上传由 CPU / 存储 / 网络完成。

- 候选为固定输入尺寸的 CNN 检测器与人脸特征网络，例如 SCRFD 类、MobileFaceNet 或 ResNet 类模型；尚未选定或验证。
- 模型需经过算子兼容检查、校准量化、离线编译和板端正确性验证。
- 不能因为 ONNX 模型可在 CPU 上运行，就认定它可直接在 NPU 上运行。
- 必须比较量化前后的人脸检测结果、特征相似度及人物聚类质量。
- CPU / NPU 特征向量是否兼容需验证；保存模型与预处理版本，升级时支持重建索引。
- 保留 CPU 推理路径；NPU 的性能收益、吞吐量和功耗均待实测。

### 3.3 PVE 与推理服务边界

- 先在裸机 Debian 上验证具体模型与 NPU 软件栈，再验证容器或虚拟化部署。
- 拟将推理封装为独立服务，由相册通过内部接口调用。
- PVE 虚拟机内置 NPU 直通尚未验证，不作为已具备能力或首版承诺。
- 如 LXC 设备映射或宿主侧推理服务可行，可与相册虚拟机配合；最终方案以实测为准。
- 文献实验环境不能直接视为 MS-R1 当前系统可用配置，需记录 SDK、KMD、UMD 与模型编译目标的匹配关系。

## 4. 实现路线尚未确定

优先评估以下方案，而非现在锁定技术栈：

| 路线 | 需验证的问题 |
| --- | --- |
| 复用 Immich / PhotoPrism，加独立归档服务 | ARM64 支持、接口能力、原片去重语义、人脸推理后端替换方式 |
| 自建轻量照片管理服务 | 首版范围、上传体验、人物相册与长期维护成本 |

115 接入需验证可用接口、账号授权、上传限制、失败恢复及远端校验能力，不预先承诺某个客户端或库可用。

## 5. 分阶段计划

1. **需求确认**：明确首版范围、数据规模、用户模式和备份策略。
2. **技术验证**：NPU 人脸模型、115 加密包上传与恢复、PVE 部署分别做最小验证。
3. **最小可用版本**：照片上传、SHA256 去重、后台任务、增量加密备份与状态查看。
4. **人物相册**：接入经过验证的人脸流水线与人工纠正功能。
5. **稳定性完善**：故障恢复、任务重试、索引重建及部署文档。

若 NPU 验证不通过，需明确报告限制，再决定 CPU 方案与首版性能目标。

## 6. 首版拟议验收标准

- 同一文件连续上传或并发上传，最终均只保留一份原片。
- 重复上传不会重复进入后续归档包。
- 上传成功后的照片可浏览，后台任务状态可查询，失败可重试。
- 云端归档包及恢复清单均受加密保护，无法直接读取原始照片和文件名。
- 上传中断后重试不会产生重复归档记录或错误的成功状态。
- 从 115 下载归档，在独立恢复环境中解密，恢复照片的 SHA256 与原始值一致。
- 人脸识别能对测试照片分组，并允许纠正误分；识别准确率和速度目标在样本测试后确定。
- 若启用 NPU，提供与 CPU 的准确率和端到端性能对照，证明主推理实际运行在 NPU。

## 7. 待确认事项

- [ ] MS-R1 内存容量、磁盘布局、当前 Debian / 内核 / BIOS 版本。
- [ ] 照片总量、总容量、每日新增量，以及首轮导入可接受时间。
- [ ] 单用户还是家庭多用户；是否需要独立账号和相册权限。
- [ ] 首版是否仅支持照片；是否纳入视频、RAW、HEIC、Live Photo。
- [ ] 上传入口：网页、手机自动备份、目录扫描分别需要哪些。
- [ ] 人物自动归类是否足够，是否需要预录姓名后识别指定人物。
- [ ] 复用现有相册还是自建；是否有明确的界面和移动端要求。
- [ ] PVE 是否为必选，是否接受独立的 NPU 推理服务。
- [ ] 115 授权方式、可用容量、打包触发策略、归档包大小与密钥保管方式。
- [ ] 删除照片如何影响备份；保留历史归档还是同步删除，保留期多长。
- [ ] 本地原片保留策略；首版暂按持续保留设计。
